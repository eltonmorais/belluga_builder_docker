# Deterministic local tooling register

Project-local deterministic supports and their current boundaries:

| Support | Classification | Owner / entry point | Status | Authority and limitations |
| --- | --- | --- | --- | --- |
| Prototype authoring | `partial-tool` | `skills/create-prototype/SKILL.md`; `local-api/artifact-status prototypes --mode working-tree|committed` | Skill plus deterministic structural validator; candidate authoring remains judgment-led and separately consumes Design System provider output for version binding. | Prototype results remain `local_structure_only` with `design_system_validation:not_evaluated`. The skill compares reference ID and full provider inventory digest at the required Foundation revision; a match identifies a version only, not Prototype CSS/component use, aesthetics, accessibility, QA, preview, publication, remote freshness, or review approval. |
| Design System structural provider | `partial-tool` | `skills/create-design-system/SKILL.md`; `local-api/artifact-status design-system --mode working-tree|committed` | Local whole-source provider and authoring guidance; consumer convergence remains with downstream skill owners. | Explicit trusted `source-bindings.json`; Project → Company → default, no key merge/fallback. Full `inventory_digest` is the consumer reference; not IAM, general accessibility, visual approval, preview, or publication. |
| Executive Landing authoring and Project review packet | `partial-tool` | `skills/create-executive-landing/SKILL.md`; existing `local-api/knowledge-status` and `local-api/artifact-status design-system` operations | Executive judgment and image exploration remain skill-led; existing Project status/review-packet and Design System operations support only their defined evidence checks. No new tool or second authority is implied. | Fresh stdout is bound to Project `builder`; the snapshot is not live evidence. Review-packet output identifies the exact committed source/output and packet digests. `record-review` is only for a human-approved exact packet. Never use Project adapters or status/revision as Company evidence, Design System conformance beyond the defined structural/version checks, preview integrity, remote freshness, publication, or authorization. |
| Public Builder preview | `already-backed` | Builder fixed document catalog and existing preview service | Existing, unchanged | No Prototype catalog, code, assets, or local status snapshot is exposed by this support. |

The `artifact-status` runner uses Docker's Go 1.23 Alpine toolchain and executes the temporary binary as the invoking host UID/GID. Its stdout belongs to that invocation; the fixed JSON file is a disposable shared last-writer-wins snapshot. Exit 0 is structural `go`, 2 is valid structural `no_go`, 64 is usage error, and 70 is infrastructure failure. For 64/70, no new snapshot is written. No host Go installation is required.

These local supports are transitional and are not public APIs or authorization services. Retire an adapter only after a separately authorized project-bound equivalent is available and its consumers have migrated.
